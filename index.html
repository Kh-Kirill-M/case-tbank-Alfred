Альфред, друг Бэтмена

Система отслеживания сбоев рейсов в сервисе TravelTech
О кейсе. TravelTech: сервис планирования путешествий. Нужно спроектировать систему, которая отслеживает статус рейсов через API авиакомпаний или их рассылки, уведомляет о задержке или отмене, предлагает альтернативные рейсы или активности и обновляет общий план поездки.

Условия. Данные о рейсах приходят с задержкой, пользователь может быть офлайн, альтернативы должны учитывать багаж, визы и часовые пояса. Уточнить требования у заказчика нельзя, поэтому решение начинается с допущений.
Ограничение: нельзя хранить паспортные данные дольше, чем необходимо для поездки. В решении они хранятся отдельно, номер зашифрован, а удаляются после фактического прилёта последнего рейса (п. 8).

Разделы решения

Главная / Допущения

1. Допущения

№Допущение
1Сервис сам продаёт билеты, поэтому может предложить и оформить другой рейс. Обмен идёт по правилам тарифа авиакомпании. Доплату, если она есть, принимает существующий платёжный модуль.
2Новый рейс бронируется только после подтверждения пользователя.
3Уведомляем об отмене, о задержке от 30 минут и о любой задержке, из-за которой срывается пересадка или другое событие плана. Пересадка считается сорванной, если до следующего рейса остаётся меньше минимального времени пересадки в этом аэропорту. При отмене или сорванной пересадке предлагаем альтернативные рейсы. При задержке без смены рейса предлагаем перенести трансфер и активности, при ожидании от 3 часов — активности рядом с аэропортом.
4Статус рейса берём из двух источников: API авиакомпании (основной) и рассылки авиакомпании (запасной). Данные сравниваем по времени изменения статуса у авиакомпании, а не по времени получения; при равенстве приоритет у API. Если оба источника недоступны дольше 15 минут, показываем «статус не подтверждён».
5Если авиакомпания сама пересадила пассажира на другой рейс, альтернативы не предлагаем, а обновляем план и проверяем зависимые события. Если новое время срывает пересадку или другие события, действуем по п. 3.
6Сначала отправляем push. Если его не доставили или не открыли за 10 минут, дублируем по SMS и email. Предложение действует 30 минут, после этого варианты пересчитываются при следующем входе. Перед бронированием заново проверяем наличие мест и цену. Если пользователь так и не ответил, ничего не меняем: остаётся вариант от авиакомпании.
7В групповой поездке уведомления получают все, решение принимает организатор. Группа летит вместе: предлагаем только рейсы, где хватает мест на всю группу. Если таких нет, сообщаем организатору и передаём в поддержку. Багаж и визы (п. 11) проверяем для каждого участника.
8Паспортные данные удаляются автоматически после окончания поездки, то есть после фактического прибытия последнего рейса. Если поездка затянулась из-за задержки, удаление переносится.
9Время хранится в UTC, а показывается по местному времени точки события: аэропорта, отеля, места трансфера.
10Отслеживаем статус только авиаперелётов. Трансфер, отель и активности не отслеживаем, а только пересчитываем и переносим, когда меняется рейс. Компенсации за задержку не рассматриваем.
11Предлагаем только рейсы, где норма багажа не меньше, чем в исходном билете, и маршрут не требует визы, которой у пассажира нет (в том числе транзитной).
12Активности подбираются внутри системы по плану и интересам пользователя. Партнёрам передаются только данные, нужные для брони (имя, даты). Паспортные данные передаются только авиакомпании при бронировании рейса.
Главная / Участники и внешние системы

2. Участники и внешние системы

С системой работают три роли пользователей, оператор поддержки и шесть внешних систем.

Контекстная диаграмма C4

В систему «Альфред» входят отслеживание рейсов, подбор альтернатив, перебронирование рейса и план поездки. Первичная покупка билетов, поиск отелей и рекомендации относятся к соседним модулям сервиса TravelTech. В обработке сбоя они не участвуют, поэтому на диаграмме их нет.

Пользователи

УчастникЧто делает в системе
ПутешественникВводит паспортные данные и визы, получает уведомления о сбое, выбирает альтернативу, смотрит обновлённый план.
Организатор группыВсё то же, что путешественник, плюс выбирает альтернативу за всю группу.
Участник группыВводит паспортные данные и визы, получает уведомления и видит обновлённый план, но не принимает решение за группу.
Оператор поддержкиРазбирает сбои, которые система не решила автоматически: нет мест на всю группу, не удалось забронировать рейс.

Внешние системы

СистемаЗачем нужна
API авиакомпанийСтатус рейса и изменения брони, тарифы и нормы багажа, поиск и бронирование нового рейса.
Почта (рассылки авиакомпаний)Запасной источник статуса рейса.
Справочные данныеВизовые требования и минимальное время пересадки по аэропортам.
Сервисы партнёров (отели, трансферы, активности)Перенос броней из-за сдвига рейса, подбор активностей.
Сервис уведомлений (push, SMS, email)Доставка уведомлений пользователям и статус доставки.
Платёжный сервисОплата доплаты, если новый рейс дороже.
Главная / Сценарии

3. Сценарии

Диаграмма вариантов использования показывает, кто какими функциями системы пользуется. Основной сценарий и альтернативные варианты разбирают по шагам один случай: авиакомпания отменила рейс.

Диаграмма активности

Сценарий «Обработка сбоя рейса»

УчастникиПутешественник (в группе – организатор), система «Альфред»
ПредусловиеУ пользователя есть поездка с рейсом, который отслеживается
ТриггерОт API авиакомпании или из рассылки пришло изменение статуса рейса
РезультатПользователь летит новым рейсом, план поездки обновлён
  1. Система получает новый статус рейса из API авиакомпании или из рассылки.
  2. Система сравнивает его с текущим по времени изменения у авиакомпании и сохраняет более свежий (п. 4).
  3. Система определяет, что рейс отменён (п. 3).
  4. Система находит события плана, которые затронет отмена: пересадку, трансфер, отель, активности.
  5. Система подбирает альтернативные рейсы: есть места, багаж не меньше исходного, не нужна новая виза (п. 11). Время показывается по местному времени аэропорта (п. 9).
  6. Система отправляет push-уведомление об отмене со списком альтернатив.
  7. Пользователь в течение 30 минут выбирает альтернативу.
  8. Система заново проверяет наличие мест и цену (п. 6).
  9. Пользователь подтверждает обмен и оплачивает доплату, если она есть (п. 1, 2).
  10. Система бронирует новый рейс через API авиакомпании.
  11. Система обновляет план поездки и переносит затронутые брони через сервисы партнёров.
  12. Система отправляет уведомление с обновлённым планом.

Главная / Статусы рейса

5. Статусы рейса

У отслеживаемого рейса шесть статусов. Система реагирует на переходы между ними: именно переход запускает процесс из раздела «Схема процесса».

Диаграмма состояний рейса

«Запланирован» и «Задержан» объединены в составное состояние «Ожидает вылета»: из любого из них рейс может быть отменён, вылететь или потерять связь с источниками. Круг «H» означает историю: когда данные снова пришли, рейс возвращается в тот статус, в котором был до потери связи.

СтатусКогда наступаетЧто делает система
ЗапланированРейс добавлен в поездку или задержку отменилиСледит за статусом
ЗадержанВремя вылета сдвинулосьУведомляет при задержке от 30 минут или срыве пересадки (п. 3)
ОтменёнАвиакомпания отменила рейсУведомляет и подбирает альтернативы (п. 3)
Статус не подтверждёнОба источника молчат дольше 15 минут (п. 4)Показывает пользователю последний известный статус с пометкой и продолжает запрашивать данные
ВылетелРейс вылетелПрекращает подбор альтернатив, следит за временем прилёта
ПриземлилсяФактическое прибытиеЗаканчивает отслеживание. Если рейс последний в поездке – удаляет паспортные данные (п. 8)

7. Итоговая сводка

Каждое условие кейса и то, как оно учтено в решении.

Данные о рейсах приходят с задержкойСтатусы сравниваются по времени изменения у авиакомпании, а не по времени получения. Опоздавшее старое событие не перезаписывает более свежее.
Отказы внешних APIПочта — запасной источник статуса. Если оба источника молчат дольше 15 минут — статус «не подтверждён». Если не удалось забронировать — повтор, затем поддержка.
Пользователь может быть офлайнPush, через 10 минут – SMS и email. Предложение действует 30 минут, затем пересчитывается при входе. Без ответа ничего не меняется.
Альтернативы учитывают багажПредлагаются только рейсы с нормой багажа не меньше исходной. Нормы берутся из API авиакомпаний.
Альтернативы учитывают визыМаршрут проверяется по справочным данным для гражданства и виз каждого участника, включая транзитные визы.
Альтернативы учитывают тайм-зоныВремя хранится в UTC с часовым поясом места и показывается по местному. Пересадки и сдвиги считаются в UTC.
Конфликты расписаний и пересадокПересадка срывается, если до следующего рейса меньше минимального времени пересадки. Связь «зависит от» находит все затронутые события плана.
Обновление общего планаПосле перебронирования система переносит брони партнёров и рассылает новый план всем участникам. Если партнёр не даёт перенести бронь – сообщает пользователю.
Групповые поездкиУведомления получают все, решает организатор. Предлагаются только рейсы с местами на всю группу, иначе случай уходит в поддержку.
Персонализация без утечки данныхАктивности подбираются внутри системы. Партнёрам передаются только данные для брони (имя, даты), паспорт – только авиакомпании при бронировании.
Паспортные данные не дольше, чем нужноХранятся отдельно, номер зашифрован. Удаляются после фактического прилёта последнего рейса; если поездка затянулась, срок сдвигается.
